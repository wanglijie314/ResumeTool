# 简历一键填 · 项目介绍（背景 / 问题 / 方案 / 结果）

> 面向介绍与汇报的完整叙述版。安装与使用步骤见仓库根目录 `README.md`，会话接续信息见 `docs/PROJECT_STATE.md`。

**一句话概括**：一个 Chrome/Edge（Manifest V3）扩展——扫描招聘网站表单、按你的资料副本自动填写；没见过的字段教一次就全局记住；本地解析简历文件；**默认纯本地算法，AI 可选（自带 Key）**。

---

## 一、项目背景

国内招聘网站与企业自建招聘系统（ATS）的报名表单，字段叫法五花八门、控件实现各异。投一次简历往往要重复手填几十个字段（基本信息、联系方式、教育经历、实习/工作经历、项目经历、获奖、求职意向……），多投几家公司就是成倍的重复劳动，还容易填错、填漏。

同时带来三个现实约束：

1. **简历文件要反复用**：每次都要重新打开 PDF/DOCX 复制粘贴；不同岗位还需要不同版本的投递资料（校招版 / 社招版 / 实习版）。
2. **字段是"活的"**：每个站点字段名、顺序、控件类型都不同，规则写死必然覆盖不全，需要能"越用越准"。
3. **隐私敏感**：简历含手机号、身份证号等信息，不能随意上传第三方。

由此确定产品目标：一个**本地化、可学习、AI 可选**的浏览器扩展——
识别字段 → 自动填写 → 未识别字段可教学并全局记住 → 多套信息副本 → 本地简历解析 → AI 仅在用户主动配置时作为"建议级"增强。

## 二、遇到的问题

### 2.1 识别层

| 问题 | 具体表现 |
| --- | --- |
| 标签来源不统一 | 字段名可能藏在 `aria-labelledby`、`label[for]`、包裹式 `label`、`aria-label`、前置文本、`placeholder`、`name/id` 任一处 |
| 控件非原生 | 下拉/日历绝大多数是自定义组件（div + JS），不是原生 `select`/`date` |
| 猜错比不填更糟 | 把"期望城市"错填成"籍贯"的代价，远高于留空让人工补 |

### 2.2 交互与资料层

- **未识别字段没有出路**：最初只能"跳过"，用户无法把新字段沉淀下来。
- **经历类是多实例的**：实习/项目在页面上常是"多行组合控件"（公司/岗位/时间/描述各一格，可"添加一行"），把多段经历塞进一行 = 灾难性错填。
- **多版本资料**：同一份档案无法同时适配校招与社招。

### 2.3 简历解析层（纯文本 → 结构化）

- PDF/DOCX 抽出的文本没有统一结构，同义标签遍地（毕业院校/院校/学校名称……）。
- 多段经历容易串行；公司名会被日期碎片污染（`2021.07-2021.10` 被当成公司词元）。
- 全角分隔符、无冒号的紧凑段落会破坏切段规则。

### 2.4 工程层（实际踩坑）

- MV3 Service Worker **没有 DOM**：扫描/填写只能放内容脚本，AI 请求必须走后台或扩展页以避开页面 CORS。
- **CRXJS + Vite 8 的 SW loader 错位**：生成的 `service-worker-loader.js` 指向了内容脚本 chunk，导致 SW 顶层访问 `document` 直接崩溃 → 用后置脚本 `scripts/fix-sw-loader.mjs` 重写入口修正（已并入 `npm run build`）。
- 自定义下拉/日历需模拟 `mouseover/mousedown/mouseup/click` 事件序列，日期另需"直接写值"兜底。
- 扩展重载后旧页面脚本失效 → 必须有明确的 `stale-extension / inject-failed` 提示，而不是静默失败。

### 2.5 隐私与 AI 的边界

- 不能让 AI 直接改写用户资料，也不能把"用户填写的值"发给模型。
- 因此 AI 只允许产出**建议**：先落"建议表（pending）"，用户点头后才生效。

### 2.6 AI 接入后的实测问题

- 页面字段识别一次请求（约 1.4k 字符）实测 **~50s** 才返回，而连接测试只要 **2.5s** → 定位为**免费/低成本档模型排队与推理慢**，不是链路或代码问题；据此把超时提到 120s（简历补全 180s）。
- 弹窗在等待期间被关闭会丢回传结果（虽然建议已落库）→ 补上"等待秒数提示"与"重开弹窗自动捞回 pending 建议"。

## 三、解决方案

### 3.1 扫描与识别（先认字段）

- 标签多来源按优先级取值：`aria-labelledby` → `label[for]` → 包裹 `label` → `aria-label` → 前置文本 → `placeholder` → `name/id`；同时判定 `kind`（text/textarea/select/原生日期/自定义 widget/radio/checkbox）与 `widget`（date/choice）。
- 分类器优先级：站点忽略 → 全局词表（教学 `taught` / 别名 `alias`）→ 内置词典加权 → 单选项文本兜底；低于置信度门槛（0.6）宁可不填。
- 高敏感字段（身份证 🔒）填写前由用户二次确认。

### 3.2 教学闭环（认不出来就教会它）

未识别字段 → 教学浮层给出四条路：**新增自定义字段**（默认建议，名字取自真实标签）/ 归类到已有字段 / 本站忽略 / 跳过。
教过的"页面文本 → 标准字段"进入全局词表，**跨站点生效**；自定义字段以 `custom:名称` 为键，与内置字段同权参与识别、填写与别名管理。

### 3.3 填写执行（填得准，不乱填）

- `filler` 按控件类型分策略；`widgets` 负责自定义下拉（文本相似度 ≥0.6 取最佳项 + 模拟事件）与日历（点选，失败则直写兜底）。
- **按段填经历**：`rowFill` 探测页面"行组合"（含"添加一行"按钮、heading 归属），按结构化经历逐段增行填写；页面只有一组组合时**只填第一段并明确提醒剩余未填**，绝不合并、绝不串行错填。

### 3.4 资料层（多副本 + 结构化经历）

- 多份 `ProfileCopy`（条目 + 结构化经历块 `blocks` + 自定义字段 `custom`），互相独立；页面里补充的信息只写入默认副本。
- 结构化经历与"整段文本"双向同步：整段由结构化块自动重算，用户只维护结构化子字段。
- 本地简历解析（PDF/DOCX/TXT，PDF 走 pdfjs worker）固定口径：实习 = 公司/岗位/时间段/描述；项目 = 名称/职责/描述；多段各自成块保序；时间统一 `xxxx.xx`；解析结果进入**可编辑预览**，确认后"另存为新副本"或"合并到当前副本"。

### 3.5 AI 可选层（自带 Key，建议级）

两处增强，共用一条通道（`/chat/completions` + `response_format=json_object`）：

| | 页面字段识别（skill `page-match`） | 简历解析补全（skill `resume-extract`） |
| --- | --- | --- |
| 输入 | 未识别控件的 标签/提示词/形态/选项示例 | 简历原文 + 规则已解析字段 |
| 输出 | 字段键建议（白名单枚举，越权键丢弃） | 补全的标量字段（仅内置键、按类型截断、同键留高置信、已有键 conf≥0.9 才覆盖） |
| 落地 | 建议表 `pending`；**接受**才写入全局词表并自动重扫 | 进入可编辑预览草稿；另存/合并才写入副本 |
| 触发 | 弹窗手动点「AI 识别」 | 填了 Key 时每次导入自动执行 |

- **可观测**：每次真实模型请求都落一条本地日志会话（用途 / 模型 / 端点 / 耗时 / HTTP 状态 / 错误码），简历补全另有流程事件（文件名、遗漏行数、新增·修正·忽略数）——在「运行日志」里可直接确认"是否真的走了 AI"。
- **降级**：没填 Key → 不调用、不发送，完全使用内置算法；调用失败 → 退回规则结果，绝不阻塞；清空 Key 保存即彻底关闭 AI。

### 3.6 隐私与本地化

- 所有数据（副本、词表、设置、日志、AI Key）只存 `chrome.storage.local`，不上传服务器。
- 外发仅两类且都需用户主动配置 Key：页面字段识别发**控件元数据**（不含填写值）；简历补全发**简历片段与上下文（≤2 万字）**。
- 运行日志环形保留（最近 20 会话 / 1 天 / 单会话 200 条），支持一键导出 `.txt`。

## 四、最终结果

### 4.1 已实现能力（开发预览 v0.2.0）

| 里程碑 | 内容 | 状态 |
| --- | --- | --- |
| M0 | MV3 + Vite + CRXJS 骨架、图标、manifest | ✅ |
| M1 | 扫描与识别（多来源标签、kind/widget、置信度、可拖动识别面板） | ✅ |
| M2 | 多副本资料 + 弹窗填写 + 简历导入预览 + 运行日志 | ✅ |
| M3 | 教学闭环（全局词表 taught/alias、自定义字段、站点忽略） | ✅ |
| M4 | 经历多行组合驱动（行角色探测、按段增行填写、剩余提醒） | ✅ 代码级（真实站点形态待收敛） |
| M5 | AI 字段识别底座（建议级 + 日志审计） | ✅ |
| M6 | 简历解析 AI 补全（流程日志 + 失败降级） | ✅ |

### 4.2 质量与工程

- `npm run typecheck` 0 错误；
- 单测全绿：分类器 62 项、keys/相似度 6+7 项、行角色 25 项、简历解析 45 项 + DOCX 抽取、AI 契约 11 项 + 简历补全 26 项；
- `npm run build` 通过（含 SW loader 修正后置脚本）；
- 附带演示页 `pages/demo.html`（自定义下拉、日历、多行组合三种场景）。

### 4.3 使用效果

一次配置、多站复用；不认识的字段教一次即长期生效，**越用越准**；多套副本适配不同投递方向；简历文件本地解析成结构化资料；AI 全程"建议级 + 可审计 + 可一键关闭"。

### 4.4 已知边界与后续

- 真实站点的行组合 DOM 形态仍需实测收敛（探测失败会明确提示，绝不乱填）；
- 地域省市下拉的通用驱动（方案已定，待开发）；
- 扫描版 PDF 的 OCR 未做；简历 AI 补全暂限内置标量字段（"AI 新建自定义字段"待落地）；
- 教学命中计数、站点级词表开关等体验项待补。
